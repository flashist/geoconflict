# Profile Identity S2 — `POST /v1/login` and the stateless 24 h session token

**Source**: `ai-agents/tasks/done/0271-profile-identity-s2-login-endpoint-and-session-token/brief.md`
**Status**: done (agent-closed — not owner-verified)
**Sprint/Tag**: Sprint 4 / task `0271` / slice S2 of epic `0266`

## Goal

Ship the login endpoint and the session token **in v1** — the owner's ruling *"Token now, not later"*,
which **overruled the architect's recommendation to defer it on timing**. See
[[decisions/adr-113-internal-player-id]].

> 🔓 **Security gained today: none — say it that way.** Anyone who asserts a Yandex id gets a token. What
> the token buys is **Yandex ids out of URLs and logs** and **one place to verify later** (`0267`).
> ⛔ **A `vfy:false` token must never count as a proven owner** — e.g. for paid state (`0250`).

**Owner-accepted risk, recorded not re-argued:** **no per-IP limiter on login.** Monitoring (S5) replaces
it; junk profile rows are the accepted, monitored risk.

## Key Changes

1. **`LoginContract`** — request `{ platform, platformUserId }` (1–128 chars), response
   `{ created, profile, grantChecks.tenure, session { token, expiresAt } }`; errors `400 bad_request` ·
   `503 session_unavailable` · `500 internal_error`.
2. **`POST /v1/login`** — validation, `resolveOrCreatePlayer` (S1), `created`, `grantChecks.tenure`
   (`done` iff a tenure grant row exists, **any amount**), the public profile (**no platform id, no player
   id**), and a token. **No limiter.**
3. **`SessionToken`** — `v1.<payload>.<HMAC-SHA256>`, payload `{pid, plt, iat, exp, vfy:false}`, TTL 24 h,
   **constant-time MAC compare** (the `InternalAuth.ts` pattern).
4. **`resolveCaller`** — valid Bearer token first → legacy Yandex-id fallback (**find-only, never
   creates**) → `401` with `session_expired` / `session_invalid`. **Every public route takes its caller
   from it**, payments intent included.
5. **CORS** — `Authorization` allowed, `Access-Control-Max-Age` set on all public routes, `OPTIONS` → 204.
6. **`PROFILE_SESSION_SECRET`** — generated by `setup-profile.sh` into the 0600 env file, forwarded by the
   deploy script, in the config-parity allowlist, asserted by the hardening harness. **Fail closed:** empty
   ⇒ login and token routes `503 session_unavailable` plus a boot `warn` **naming the variable, never its
   value**. ⚠️ Coordinated with `0220`'s persist-or-reuse pattern — **a secret regenerated on every deploy
   only forces a silent re-login (no data loss), but it was decided deliberately, not left accidental.**

### Verification step 8 — both halves met live

| Check | Result |
|---|---|
| First login, synthetic id | `created=true`, `grantChecks.tenure="pending"`, **token received** |
| Profile GET **with that Bearer token** | **200**, full profile body — **acceptance proven** |
| Token with one character altered | **401** — the signature is genuinely verified, **not decorative** |
| `Authorization: bearer …` (lowercase prefix) | **401** — strict `Bearer ` parsing confirmed live; this was **S2 residual R3**, now settled |
| Second login, same id | **`created=false`** — find-or-create correct, no duplicate profile |
| Synthetic id in container logs | **0 occurrences** |
| Any session token in container logs | **0 occurrences** |
| Error-level log lines since boot | **0** |
| Cleanup (one transaction) | back to **0 players, 0 identities** |

🚩 **Why the second row mattered.** **Signing a token and verifying one are separate paths**, and
`resolveCaller` is what every public route depends on. **A token that is issued but not accepted would
have presented exactly as the box did before this run**, and would have surfaced only once the client
shipped under `0273`. The earlier 401 on an *unauthenticated* profile GET proved the **legacy fallback was
gone**; it said **nothing** about Bearer acceptance. It does now.

The container-log grep is also the **live proof of verification step 5** (*"no token, Yandex id or player
id appears in any log line"*), which until then rested only on a test asserting over captured log output.

📌 **Re-runnable box evidence to inherit:** alongside these login checks, the `/internal/` boundary was
proven on the box under `0276` — **eleven read-only probes from a non-allowed host and one from the allowed
game box**. `0279` and `0217` should **re-run that set rather than rediscover it**.
