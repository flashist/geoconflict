## Accepted residuals (shared, do-not-re-litigate)
- **ENOSPC partial persist write (the four dotfiles AND `.internal_token`; reviewer Q3)** — What: `printf '%s' > file` under a full disk can leave a *truncated* file; `-s` (or the token block's `-f`) accepts it on the next blank deploy, so a truncated value is "reused" — a wrong value, not an empty one. Same property `.internal_token` has carried since 0182. · Why (structural): closing it needs write-to-temp + fsync + rename per file, or a hash/length sidecar — more machinery than four optional values warrant, a length sidecar would carry the very thing the output must never carry, and a full disk fails the same deploy loudly elsewhere (compose write, image pull, Postgres). A wrong Telegram/Yandex value fails at use, not silently. Rejected: temp+rename (machinery; and the token block would have to follow), size/hash sidecar (leaks a length). · Re-raise only if: a persist file is observed truncated on the box, or the token block gains an atomic write (then the four should follow it). *Recorded on the driver's instruction under the sprint-loop standing approval (ADR-032) — the driver relays; not a direct owner ruling on this line.*
