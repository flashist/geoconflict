## Accepted residuals (shared, do-not-re-litigate)
- ssh-alerts journal filter trusts SYSLOG_IDENTIFIER (R6; owner-ruled 2026-10-12, "Accept as known limit") — What: the login watcher (and the daily count) filters the journal by `SYSLOG_IDENTIFIER=sshd` / `sshd-session` only, so a local account can write a line that produces a FAKE login alert (it can never hide a real one) · Why (structural): every trusted-field filter (`_UID=0`, `_COMM`, `_SYSTEMD_UNIT`) is unverified on the four boxes, `_COMM` can be faked by running a copied binary named `sshd`, and a wrong filter would silently drop every login alert on that box — noise was judged cheaper than a missed login · Re-raise only if: a box gets untrusted local accounts, OR a read-only check shows `_UID=0` on the `Accepted` lines on all four boxes (then the stricter filter is safe to add).
