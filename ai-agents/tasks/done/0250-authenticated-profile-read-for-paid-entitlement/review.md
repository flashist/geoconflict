**Round 3 (slice S3b, 2026-10-06) — no novel findings; no rows added.** Checked against the code, with the five focus points:
1. *Unverified bodies are the same as S1.* Every channel routes `verified === false` to the unchanged S1 function: `profileForCaller` → `toPublicProfile`, `xpForCaller` → `equalizedXp`, `inboxMessagesForCaller` → `toPublicInboxMessages` (src/profile-server/PublicProjection.ts:105-131). The PATCH by-id and mark-all flows keep the same `hiddenInboxMessageIds` set and the same two `markRead` calls (src/profile-server/Routes.ts:1229-1241). The only wire difference for an unverified caller is the owner-approved choice (c), `Cache-Control: no-store` on the 200 answers of `GET /v1/profile` and `GET /v1/messages` (Routes.ts:682, :1188). It depends only on the route.
2. *A verified caller sees only itself.* `verified` is `claims.vfy === true` from the server-signed token (Routes.ts:333-334). Login signs the same local `verified` it uses for the view (Routes.ts:758-821). `vfy:true` is minted only when the signed id equals the asserted id (src/profile-server/LoginVerification.ts:45-54). `PlatformSchema` has one value (src/core/profile/Platform.ts:11). No player-facing route takes a target id. On the client, the in-memory session drops its token when the Yandex id changes (src/client/ProfileSession.ts `resolveSession`), so a second account on the same device never reads the first account's owner view.
3. *`isPaidCitizen` fails closed.* It is `isOwnerView && profile.is_paid_citizen === true` (src/client/PlayerProfileView.ts:126, :144). Every zero-state sets it to false. A body that fails the schema gives the zero-state. A purchase date without `is_paid_citizen` does not count as the owner view.
4. *Earned:XP paid rule.* Verified against the SQL: `GRANT_CITIZENSHIP_SQL` stamps `citizenship_earned_at = coalesce(…, now())` for any player who crosses 100, paid or not (src/profile-server/PlayerProfileRepository.ts:108-116). The paid grant sets `citizenship_purchased_at = coalesce(…, now())` (src/profile-server/PaymentsRepository.ts:50). So `purchasedAt > earnedAt` correctly separates "earned first, paid later" from "paid first". Unverified reads touch no storage (PlayerProfileView.ts:126-133). `earnedBeforePurchase` (:209) suppresses null and NaN dates.
5. *Cross-deploy.* zod 4 `z.object` strips unknown keys. So an S1-era client parses an owner body with the paid keys dropped, and the new `.optional()` keys parse an S1 or older-server body. Both are tested in tests/core/profile/PlayerProfile.test.ts. The first commit whose client sends a signature (`df3c6b3`) has S1 (`68303d5`, which introduced the `_v2` prefix) as an ancestor (checked with `git merge-base --is-ancestor`). So no pre-S1 bundle can reach an owner view. The S1 client already knows the `citizenship_paid` / `citizenship_earned` inbox keys (src/core/profile/InboxContract.ts:38-39).
