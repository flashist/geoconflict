## Accepted residuals (shared, do-not-re-litigate)
- **Closing a joined private lobby's window does not leave it (0303 R1)** — What: a purchase made after joining someone's private lobby and closing that window (X, Esc, outside click) marks the restart offer pending, and it never shows that page load unless the player later joins and leaves another lobby; if the host starts the match it is dropped (the page reloads after the match anyway). The player gets the accepted "Later" behaviour. · Why (structural): the cause is not 0303's — `JoinPrivateLobbyModal.close()` does not send `leave-lobby` and `closeAndLeave()` has no callers, so the player stays connected to the lobby and `gameStop` stays set; that predates 0303. Fixing it inside 0303 (making close leave, or treating "window closed" as "on the start screen") changes lobby behaviour outside the plan. Owner ruled 2026-09-28 "Accept in 0303, file bug (Recommended)"; the producer files the "closing doesn't leave" bug as its own task. · Re-raise only if: that bug is fixed and closing a joined private lobby then sends `leave-lobby` but the popup still does not show, or 0303's offer logic changes how `pending` is cleared.
- **Tenure gift attribution by before/after comparison (0303 R2)** — What: the card decides "the gift made them a citizen" by comparing its own status before the claim and after the re-read, so another change in the same few seconds (a failed first profile read that later succeeds; a session-start reconciliation grant landing mid-claim) shows the restart popup tagged as the gift. · Why (structural): the server's tenure answer cannot say whether the gift crossed the threshold — every citizen reads XP 100 under 0250 S1 — so a before/after comparison is the only client-side signal. A proper fix needs the server to return "this gift made you a citizen", which is outside 0303. Harm is small: in case (a) the restart is still useful; in case (b) the popup chain the plan feared cannot form because reconciliation never sends the signal. Owner ruled 2026-09-28 "Accept as harmless (Recommended)". · Re-raise only if: the server's tenure response gains an explicit "granted citizenship" field, or a popup shown this way is observed for a player who was already a citizen with a successful first read.
- **Popup closed by match start logs no outcome (0303 R4)** — What: if a grant lands while a join from the start screen is still setting up (the R3 gap), the restart popup shows and logs `Shown`; if the player taps neither button before the match starts, the pre-start step calls `onMatchStarting()` and then the modal's `close()` (`src/client/Main.ts:781`, `:800`; `src/client/CitizenshipRestartModal.ts:157`), which hides it with no `Restart` or `Later` and drops the offer. So `Shown` can have no outcome on this path. · Why (structural): the player loses nothing — the page reloads after the match, which applies the grant; the case is very rare (a purchase finishing within about a second of a lobby click, then the popup ignored); and the analytics reference's `Later` row already documents it ("The pre-match close of the popup logs nothing"). The rejected alternative — a fourth "closed by match start" event — adds an event, a reference row and a test for a very rare case. Owner ruled 2026-09-28 "Accept as documented (Recommended)" — "No code change; recorded so it isn't raised again. The analytics doc already describes it." · Re-raise only if: the popup stops being closed at match start (it is removed from the pre-start close list, or the offer no longer drops at match start), or the analytics reference's text describing the silent pre-match close is removed.
